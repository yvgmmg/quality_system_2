## Цель
Обеспечить, чтобы все проверки ввода данных в диалогах выводились в виде `MessageBox`, не закрывая форму, а введённые данные сохранялись. Также добавить вывод конкретной причины ошибки при неудачной авторизации (неправильный логин/пароль или исключение).

## Шаги реализации
1. **Диалог редактирования пользователя** (`UserEditDialog.xaml.cs`)
   - После базовых проверок (пустые поля, роль, положительный ID) добавить проверку существования цеха.
   - Реализовать метод `WorkshopExists(int workshopId)`.
   - Внутри метода создать `AppDbContext` с параметрами `DbContextOptions` (конструктор требует `options`).
   - При отсутствии цеха показать `MessageBox` с сообщением и `return;` – окно не закрывается.
   - При любой ошибке доступа к базе возвращать `false`.
   - Важно, чтобы после вывода `MessageBox` диалог **не закрывался** – это достигается отсутствием изменения `DialogResult`.

2. **Сервис авторизации** (`AuthService.cs`)
   - В `LoginAsync` после попытки получения пользователя добавить проверку `if (user == null)`.
   - При `null` показать `MessageBox` "Неправильный логин или пароль" с `MessageBoxButton.OK` и `MessageBoxImage.Warning` и вернуть `false`.
   - В `catch`‑блоке вывести `MessageBox` с подробным текстом исключения, используя `MessageBoxButton.OK` и `MessageBoxImage.Error`.
   - Это даёт пользователю понятную причину ошибки.

3. **Тестирование**
   - Попробовать ввести несуществующий ID цеха – должно появиться сообщение, окно остаётся открытым.
   - Ввести неверный логин/пароль – появляется предупреждение.
   - Сгенерировать исключение (например, отключив БД) – появляется сообщение об ошибке с трассировкой.

## Почему так?
- `MessageBox` обеспечивает мгновенную обратную связь без закрытия текущего окна, что улучшает UX.
- Разделение проверок (поля, роль, существование цеха) делает код более читаемым и поддерживаемым.
- Указание конкретной причины неудачной авторизации помогает пользователю быстро исправить ввод.

## Применение
- В любой форме, где требуется проверка вводимых данных, использовать аналогичный шаблон: проверка → `MessageBox.Show` → `return;` без изменения `DialogResult`.
- Для сервисов, работающих с внешними ресурсами, при `null`‑результате давать ясное сообщение, а при исключениях показывать детали ошибки.
